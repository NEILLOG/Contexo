# POC：Avalonia 中文輸入（注音）

目的：在正式開發前確認 Avalonia 在 Windows 與 macOS 上，注音輸入法、中文字型、深淺色與字級縮放都沒有阻擋性問題。**結果決定是否採用 Avalonia**（見文末判定標準）。

這是獨立的小程式，不依賴正式方案（`poc/` 下的 `Directory.*.props` 已隔離建置設定），可以在 T01 之前執行。

## 執行

需要 .NET 10 SDK。

```bash
cd poc/ime-avalonia
dotnet run
```

若 Avalonia 12 還原或編譯失敗，把 `ImePoc.csproj` 三個套件版本改成 `11.3.*` 再試，並在結果表記錄。

## 測試環境

至少測兩台：

| 代號 | 系統 | 輸入法 |
|---|---|---|
| W1 | Windows 11 | 微軟注音（新版，Windows 預設） |
| W2 | Windows 10 或 11 | 微軟注音「使用舊版」，或新注音（有就測） |
| M1 | macOS | 注音（系統內建「注音」輸入方式） |

## 測試項目

每一項在**左側四種位置**都要做：搜尋框、多行、清單內的輸入框、對話框（按「開啟對話框測試」）。右側事件紀錄可以協助判斷。

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 輸入「報價單」（ㄅㄠˋ ㄐㄧㄚˋ ㄉㄢ）並選字 | 文字正確出現一次，無重複、無殘留注音符號（紀錄不出現「⚠」） |
| 2 | 組字中（底線狀態）觀察 | 組字中的注音顯示在游標位置（行內），不是跑到視窗角落 |
| 3 | 按空白鍵叫出選字清單 | 選字視窗出現在游標附近，不遮住輸入框，不跑到螢幕左上角 |
| 4 | 在搜尋框選字時按 Enter 確認選字 | 只確定文字，**不出現「★ 送出搜尋」**；選完後再按一次 Enter 才送出 |
| 5 | 組字中按 Backspace | 刪除的是注音符號，不是已輸入的文字 |
| 6 | 組字中按 Esc | 取消組字，已輸入的文字不變 |
| 7 | 輸入全形標點「，。、？「」」 | 正確出現 |
| 8 | 中英切換（Windows：Shift；Mac：Caps Lock 或 Control+空白） | 切到英文時直接輸入英數；切回中文正常 |
| 9 | 連續快速輸入一長句「今天下午三點在第二會議室開採購驗收會議」 | 沒有掉字、亂序、重複 |
| 10 | 字級切到「特大 1.25」後重做 #1～#3 | 選字視窗位置仍正確（縮放後位置錯誤是常見問題） |
| 11 | 主題切換淺色／深色後重做 #2 | 組字文字與底線在兩種主題都看得清楚 |
| 12 | 「字型顯示檢查」區塊，分別在「指定中文字型」與「框架預設」下目視 | 沒有方框（豆腐字）、繁體字形正確（例如「骨」「直」不是簡體或日文字形）、罕用字有顯示 |
| 13 | 從記事本／備忘錄複製中文貼上 | 正確 |
| 14 | 滑鼠點選輸入框中間位置後輸入 | 文字插在游標處 |

## 判定標準

- **通過**：W1 與 M1 的 #1～#6、#9、#12 全部正常。→ 採用 Avalonia，進行 T01。
- **有條件通過**：只有 #3、#10 選字視窗位置略有偏移但可用，或只有 W2 有問題。→ 採用 Avalonia，把問題記入 `plan/06-open-questions.md`，並向 Avalonia 回報或尋找修正。
- **不通過**：W1 出現重複字、掉字、殘留注音、Enter 誤送出，或選字視窗無法使用。→ 先嘗試 `11.3.*` 版本；仍不通過則**回到 WPF 方案**（git 歷史中 `a3d2eb4` 版本的文件），Mac 上只驗證核心與 MCP。
