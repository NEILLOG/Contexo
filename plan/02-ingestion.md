# 02 檔案解析與切塊

## 共通原則

- 全部用 .NET 套件在程式內完成，不依賴 Office、LibreOffice、Python 或付費元件。
  - 避開 iText（AGPL）與 Aspose（付費）。
- 每個 chunk 都記錄**來源位置**：檔名、頁碼、投影片編號、工作表與範圍、標題路徑。用於引用出處與「開啟原檔」。
- 表格一律轉成 HTML（合併儲存格用 colspan / rowspan），Word、PowerPoint、Excel 共用同一套轉換邏輯。
- **內嵌檔案遞迴處理**：取出後丟回解析器，來源記為「A.pptx › 第 5 頁 › 內嵌.xlsx」，設定遞迴深度上限。
- 圖片不渲染整頁：直接從 Office 檔的 media 資料夾取出原圖，連同所在頁面的標題與文字一起送視覺模型（第二階段）。

## 各格式

### Word（.docx）

套件：`DocumentFormat.OpenXml`

- 用段落樣式（標題 1、2…）判斷章節；沒用樣式的文件，以「短段落、粗體、字較大、後接內文」的規則補判。
- 表格轉 HTML，處理 `gridSpan`（橫向合併）與 `vMerge`（縱向合併）。
- 文字方塊藏在繪圖物件中，要另外抓取。
- 修訂追蹤：取「接受所有修訂」的結果（保留 `w:ins`、略過 `w:del`）。
- 略過自動目錄；頁首頁尾視為雜訊略過；註腳與註解附在對應段落之後。
- 圖形、SmartArt、內嵌檔案的處理方式同 PowerPoint。
- 切塊：依章節切，過長再細分並保留重疊；**每個 chunk 前面加上標題路徑**（例如「採購規範 > 第 3 章 驗收 > 3.2 驗收標準」）；表格不從中間切，大表每段重複表頭。
- docx 沒有可靠的頁碼，引用出處用「文件名 + 標題路徑」。

### PowerPoint（.pptx）

套件：`DocumentFormat.OpenXml`

- 以「一頁投影片」為 chunk 單位，附檔名、頁碼、頁標題。
- 流程圖、架構圖：連接線 `cxnSp` 記錄起點與終點的圖形 ID，可精準還原「A → B」關係，轉成 Mermaid 之類的文字。
- SmartArt：從 diagram 資料檔讀出文字與層級。
- 表格轉 HTML；圖表讀取內含的數據快取值。
- **備忘稿一定要收**，資訊量常比投影片本身多。
- 內嵌的 xlsx / pptx / docx 遞迴解析；舊格式 OLE 物件（Visio、舊版 .xls）無法解析時，使用其預覽圖。
- 只有含圖片或無法解析物件的頁面才呼叫視覺模型，大部分頁面不需要 LLM。

> 背景：公司現行做法是整頁轉圖再請 LLM 解釋。改用結構化解析的原因是：乾淨環境沒有渲染引擎、逐頁呼叫視覺模型成本高且慢、視覺模型可能看錯箭頭方向或自行補出關係。

### Excel（.xlsx）

套件：`DocumentFormat.OpenXml`

Excel 的問題不在讀取，而在讀出來後用向量檢索效果差：加總、排序類問題需要整張表；數字本身沒有語意；結構自由（合併儲存格、多層標題、一頁多表）。

處理策略**依大小分流，不判斷用途**：

| 類型 | 判斷 | 處理 |
|---|---|---|
| 小表 / 表單（報價單、申請單、排班表） | 使用範圍在數百格以內 | 整張工作表轉 HTML，當成一個 chunk |
| 大表 | 超過門檻 | 產生「表格說明」做向量；內容透過 `query_table` 以 SQL 查詢 |

大表的表格說明包含：檔名、工作表名、欄位名稱、幾列範例資料（必要時請 LLM 寫摘要）。

大表內容的查詢方式採**查詢時載入**：

- 主資料庫只存登記表（`excel_tables`）與表格說明。
- AI 呼叫 `query_table` 時，當場讀 xlsx 載入**記憶體 SQLite**，執行唯讀 SQL 後丟棄。可加短時間快取。
- 好處：資料永遠最新、不重複存放、同步簡單；AI 下出寫入語句也只影響暫存資料。

表格偵測演算法（自行以 C# 實作，參考 Docling、xldetect、xlsx2semantic、excel-parser 的方法論）：

1. 非空儲存格做 flood fill，以空白列與空白欄切出多個表格區域。
2. 判斷標題列：區塊頂端多為文字、下方為數字或日期；粗體、底色加分。支援多層標題（各層用底線串接）。
3. 合併儲存格：填值到每一格，或輸出 HTML 時以 colspan / rowspan 表示。
4. 略過裝飾列：區塊最上方只有一格有值的長橫幅視為表格標題，不當欄名。
5. 每個 chunk 附上「檔名#工作表!範圍」。
6. 日期依儲存格格式轉回日期；公式取快取值。
7. 信心分數低時，把前幾十列交給 AI gateway 判斷表格範圍，結果存起來。

Python 套件（xldetect 等）**不嵌入產品**：安裝包膨脹、跨語言偵錯困難、PyInstaller 打包易被防毒誤判、小型套件有停更風險。開發時把它們當作對照組，比對偵測結果以調整規則。

### PDF

套件：`PdfPig`（Apache 授權）

- 文字型 PDF 直接抽文字，chunk 帶頁碼。
- 掃描型 PDF 沒有文字層，走 OCR（第二階段）。

### 圖片

- 有文字的圖（截圖、掃描）：OCR。Windows 內建 OCR 不保證有繁中語言包，改為打包 PaddleOCR 的 ONNX 模型。
- 純照片：需要視覺模型產生描述；若透過 AI gateway，圖片會離開本機，需在設定中說明。
- 預設關閉，標示「處理時間較長」。

### 其他格式

| 優先度 | 格式 | 說明 |
|---|---|---|
| 第一版 | .txt、.md、.csv、.json、.xml、.log | **先偵測編碼**（舊檔常為 Big5）；.csv 走 Excel 大表邏輯 |
| 第一版 | .html、.htm、.mht、.rtf | 去標籤後當文字 |
| 第二階段 | .msg、.eml | `MsgReader`（MIT），附件遞迴處理 |
| 第二階段 | .vsdx | 與 pptx 同樣用連接線還原關係 |
| 第二階段 | .odt、.ods、.odp | 政府機關常用 ODF |
| 第二階段 | .zip | 解壓後遞迴，限制大小與層數 |
| 第二階段 | .doc、.xls、.ppt | `NPOI`（Apache），.doc / .ppt 只能抽基本文字 |
| 視需求 | .tif / .tiff 掃描檔、會議錄音（Whisper ONNX） | 成本高 |
| 不做 | .pst | 請使用者先匯出成 .msg |

## 內建排除（使用者看不到、不用設定）

- 系統資料夾、隱藏檔、Office 的 `~$` 暫存檔
- `.git`、`node_modules` 等開發資料夾
- 執行檔、.dll、捷徑 .lnk、系統檔與無法處理的二進位檔
- 超過大小上限的檔案（預設 50 MB，可用下拉選單調整）
- 內容重複的檔案

## 資料夾同步

- **主力是對帳掃描**：啟動時與定期掃描資料夾，以路徑、修改時間、大小比對資料庫，判斷新增、修改、刪除；再以內容 hash 確認是否真的變更。改名、搬移不重算向量。
- `FileSystemWatcher` 只當輔助加速，不能依賴（會漏事件、程式沒開時收不到）。
- **修改**：重新解析並以單一交易替換該檔資料，查詢不會看到新舊混雜。
- **刪除**：原始檔不在就自動刪除對應資料。
- **保護機制**：
  - 整個資料夾讀不到（OneDrive 未登入、外接或網路磁碟未連線）時，**不視為刪除**，保留資料並標為「無法存取」。
  - 一次有大量檔案消失（例如超過三成）時暫停刪除，詢問使用者。
- 正被開啟而鎖定的檔案，列為「無法讀取」並自動稍後重試。
- 程式只會刪除自己建立的資料，**永遠不會刪除使用者的原始檔案**。

## 初次建立索引

- 背景佇列、進度與預估剩餘時間、可暫停、中斷後續跑。
- 先處理最近修改的檔案，讓使用者很快就能查到常用資料。
- 使用者在操作電腦時自動降速，閒置時全速。
