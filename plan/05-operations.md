# 05 維運與品質

## 效能預期

| 項目 | 一般文書機（無獨顯、8 GB RAM）粗估 |
|---|---|
| 查詢 | 數十毫秒，使用者感覺不到 |
| 初次建立索引（小模型） | 每秒數十個 chunk；數千個檔案約一到數小時 |
| 初次建立索引（bge-m3） | 慢數倍，可能整晚 |
| OCR | 每張一秒以上，單位成本最高 |
| 後續增量更新 | 數秒到數分鐘 |

以上需以目標機器實測。降低體感等待的做法：小模型 int8、背景低優先權、閒置時全速、最近修改的檔案優先、可暫停與續跑、有顯卡用 DirectML、可選擇公司伺服器。

## 版本號

- 由 git 自動產生，例如 MinVer 或 Nerdbank.GitVersioning：git tag 決定主版號，commit 數與雜湊放在組建號（例如 `1.4.2+37.g3f2a9c1`）。
- 寫入 `AssemblyInformationalVersion`，「關於」頁面、狀態列、問題回報直接讀取。
- 版本紀錄可由兩個 tag 之間的 commit 訊息自動整理，建置時一起打包。

## 問題回報

發生錯誤時（或使用者主動從「關於與問題回報」頁）匯出一個 .zip，交給管理者判斷。

| 內容 | 預設 | 說明 |
|---|---|---|
| 版本與系統資訊 | 必附 | Windows 版本、記憶體、顯示卡、Contexo 版本與組建 |
| 設定內容 | 勾選 | 金鑰與密碼一律遮罩 |
| 最近 7 天錯誤紀錄 | 勾選 | |
| 無法讀取的檔案清單 | 勾選 | 只有檔名與原因，不含檔案內容 |
| 完整資料夾路徑 | 不勾 | 可能含個人名稱 |

- 附一份 manifest 列出包含項目。
- 儲存到使用者選擇的位置（預設桌面），完成後提供「開啟所在資料夾」。
- 管理者聯絡方式由伺服器設定檔帶入；沒有就不顯示。

## 打包與發布

- `dotnet publish` self-contained，連 .NET runtime 一起帶，乾淨機器可直接執行。
- ONNX Runtime 的原生 dll 隨 NuGet 輸出，不需另外安裝。
- embedding 模型隨安裝檔發布或首次啟動下載（需評估企業網路環境）。
- 安裝程式負責：放置 Contexo（桌面程式）與 Contexo.Mcp、建立捷徑、可選擇開機自動啟動、可選擇預先加入 AI 軟體。

## 品質驗證

- 向目標使用者收集 30～50 份真實檔案（去識別化）作為測試集，涵蓋 Excel 表單與大表、含流程圖與內嵌檔的 pptx、各種 Word 結構。
- 每次修改解析規則後重跑測試集，人工檢查偵測結果（Excel 表格範圍與標題列、pptx 關係還原）。
- Excel 偵測開發時，同時以 xldetect 等 Python 套件跑同一批檔案作為對照組。
- 「試試看搜尋」同時作為檢索品質的檢查工具。
- 本機與伺服器若使用相同模型但不同精度（int8 / fp16），以測試集驗證檢索結果差異。

## 參考與競品

| 名稱 | 類型 | 與 Contexo 的差異 |
|---|---|---|
| GPT4All LocalDocs | 桌面 App 內建資料夾 RAG | 2025-02 後未再發桌面版；非 MCP |
| AnythingLLM Desktop | 桌面 App | 透過 REST API 轉接 MCP，需開著 App、需填 API key |
| mcp-local-rag / minirag-mcp / micro-rag-mcp | MCP server | 需安裝 Python 或 Node、手動改 JSON |

Contexo 的差異化：零依賴安裝與一鍵加入、深度 Office 解析、繁中環境（Big5、繁中 OCR、中文 embedding）、可接公司內部伺服器。
